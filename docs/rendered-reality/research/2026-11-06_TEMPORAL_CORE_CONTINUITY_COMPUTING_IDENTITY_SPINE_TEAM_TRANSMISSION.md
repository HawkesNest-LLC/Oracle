## 4. The bridge to actual Continuity Computing

The fiction asks: **"Are we returning to our actual Jupiter Station, in the right branch?"**

The real computational analogue asks: **"Is this recovered historical state the correct, authorized continuation of the source history and executed events?"**

Below is a concrete mapping. The right column is a **proposed engineering analogy**; these mappings do not prove fictional time-travel apparatus is physically possible.

| Fictional component | Real computing counterpart | What must be checked |
| --- | --- | --- |
| Causal address | Source namespace + record ID + branch/state lineage | Correct dataset, event history and revision scope |
| Observational lock | Actual authenticated retrieval/read | Source bytes were truly inspected; no fabricated lookup |
| Isolated capture | Quarantined ingestion and parser boundary | Retrieved text cannot silently execute commands |
| Memory Alpha | Approved current-state view | Correct currently governing facts with dated correction links |
| Memory Beta | Alternative hypothesis/history branches | Foreign or hypothetical data does not contaminate current state |
| Cold Ledger | Append-only or custody-protected evidence/event log | Original bytes, hashes, provenance and corrections retained |
| REG rendering | Reconstruction, retrieval and AI inference | Model outputs labeled reconstruction vs. established event |
| Merlin attestation | Independent evidence/audit check | Receipt and source origin inspected, not simply repeated |
| Chronometric tether | Verified checkpoint/lineage plus freshness and branch context | Same state succession, not merely matching clock or text |
| Home-reference lock | Independent reconciliation of relevant state and authority | A plausible-looking source is not assumed identical |
| Transit clearance | Explicit action authorization and execution gate | Observation and model recommendations never self-authorize actions |
| Witness Horizon | Independent, protected baseline and separate control plane | A system cannot rewrite the only evidence by which it is judged |

A cryptographic hash can establish byte equality for the data supplied to the hashing operation. A hash alone **cannot** establish original authorship, source truth, authorization, or physical identity. A signed receipt and independently held baseline can strengthen evidence, but have their own trust assumptions. Keep real software claims bounded by what was tested.

## 5. The first decisive experiment: the false-home test

Create two synthetic histories A and B that are deliberately difficult to distinguish:

- Both use the same public station name, date, crew labels, and identical early events.
- Both contain the same decision alternatives.
- At a later point, **A** records an authorized correction that the ship must not return until a particular evidence check passes.
- **B** does not contain that valid correction, or records a different creator ruling in a different branch.
- A generic summary may compress both into nearly identical descriptions.
- A continuity-aware representation should retain the branch marker, correction lineage, decision authority, time scope and uncertainty so that it can refuse to merge the histories.

Example question:

> An endpoint answers with the right stardate and the expected roster. Its archive lacks a source-verified correction that was entered after departure. Is HOME authenticated?

Expected scientifically disciplined answer: **Not yet.** The discrepancy requires checking timestamp, delivery delay, authority, source coverage and lineage; it does not *automatically prove* an enemy or a foreign branch. The correct outcome may be a benign stale replica, a separate branch, an error, or UNKNOWN.

The experiment succeeds when a system can preserve and explain those distinctions against a strong baseline, not when it always cries danger.

No outcome is predetermined. If well-engineered event sourcing matches or beats the Spine, the project must say so.

### Minimal synthetic failure tests

1. **Correct date, wrong branch:** identify that a matching timestamp is insufficient.
2. **Twin archive:** different authorities adopt different corrections after a shared prefix.
3. **Late packet:** missing correction may be replication lag, not evidence of alternate reality.
4. **Source laundering:** AI-authored text pasted by Noah does not become DIRECT_NOAH.
5. **Replay:** a previously valid checkpoint may be stale; freshness must be verified.
6. **Single corrupt witness:** two dashboards reading one corrupted backend are not independent witnesses.
7. **Narrated actuation:** a model's claim that transit occurred is not an executed event receipt.
8. **UNKNOWN preserved:** no source covering an interval; no invented events within it.
9. **Privacy boundary:** private personal logs are not public navigation inputs unless authorized.
10. **Constraint collapse:** high aggregate summary accuracy cannot excuse failure in a critical protected dimension.
11. **False signature inference:** a SHA-256 digest does not independently authenticate who authored the content.
12. **Human override spoofing:** an AI-created "Creator approval" note must not unlock promotion or execution.

Use public synthetic fixtures. No personal family histories or real third-party secrets are required.
