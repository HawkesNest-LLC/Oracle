## Research question

Modern software may preserve a resulting state without retaining the evidentiary and authority structure by which that state became accepted. Generative AI can amplify this failure because a coherent answer is not proof of a correct historical reconstruction. The question is whether a system that explicitly models sources, assertion provenance, correction time, approval authority, unresolved conflicts, dependencies, commitments and developmental trajectory can reconstruct historical states more accurately and responsibly than conventional memory or raw retrieval.

## Hypothesis

> Holding sources and other conditions constant, provenance-aware continuity objects may improve accountable long-horizon reconstruction relative to compressed summaries or isolated fact stores.

This is a **testable proposition, not a demonstrated performance result**. Its novelty relative to established event sourcing, bitemporal databases, data lineage, provenance graphs, legal evidence models, version control, knowledge representation, and AI agent memory remains an open question.

## Proposed first-class objects

| Object | Function | Integrity boundary |
|---|---|---|
| Source | Preserved evidence bytes and origin | Hashes prove byte equality, not authorship or truth |
| Claim | Scope-limited assertion | A claim is not automatically a fact |
| Status | Evidentiary or narrative state | Historical and current state remain distinct |
| Attestation | Authenticated decision and scope | Text claiming authority is not authentication |
| Revision | Append-only changes with references | Later corrections do not silently erase earlier positions |
| Conflict | Explicitly unresolved incompatibilities | Noncontradictory statements must not be labeled incompatible |
| Dependency | Source and decision graph | Copies of one source are not independent corroboration |
| Commitment | Promise, acceptance, fulfillment and release | An unexecuted promise is not a completed action |
| Branch | Scenario, simulation, or historical scope | Simulation does not auto-promote to observed reality |
| Receipt | Verifiable action record and outcome | Claimed execution requires a tool or audit record |
| Trajectory | Time-bounded development pattern | Observations, goals, inferences and forecasts are not interchangeable |

## The candidate primitive: Trajectory

The proposed **Identity + History + Trajectory** construction describes a continuity-bearing actor as persistent anchors plus recorded events plus an evidence-linked model of development. The novel-looking claim is not that time-series analysis or behavioral forecasting was invented here. Rather, the proposed integration demands that future-directed inferences are auditable, time-scoped, distinguishable from self-declared goals, and never treated as original historical evidence. Whether this warrants its own computational primitive requires prior-art comparison and experimental work.

A difficult additional problem is **prediction-induced intervention**: describing to a person or agent who it appears to be becoming may change its subsequent development. A rigorous architecture should distinguish observed transitions from forecasts and forecast-influenced outcomes, without presuming access to private intentions.

## Test design

Prepare independent, ground-truth-labeled histories with: explicit corrections; inconsistent drafts; copied-but-nonindependent evidence; valid exclusions of one hypothesis without establishing the cause; missing authorization; accepted and pending commitments; branch-isolated observations; and subjects whose declared goals change. Compare:

1. Fixed-budget compressed summary memory.
2. Raw-source retrieval at a comparable budget.
3. Source-linked continuity objects plus the same raw evidence.

Control model, corpus, retrieval affordances, token budgets and labeling. Report reconstruction accuracy, correct source citation, unsupported assumption rate, correction survival, authority errors, false conflict detection, branch leakage, commitment state accuracy, latency, storage, privacy costs and negative results. Include an explicit null-hypothesis condition. Independent reviewers should adjudicate evaluation sets and disagreements.

This observation verifies only a limited local demonstration and does not establish production security, deployed autonomy, persistent personal identity, or implementation of all objects proposed above. ## Scientific and ethical boundaries

Neither the white paper nor the reference implementation establishes consciousness, sentience, identity equivalence, mind uploading, post-biological survival, autonomous character worlds, or universal data preservation. Privacy, revocation, consent and rights over third-party materials are not optional afterthoughts. A robust witness system must distinguish original evidence, human approval, AI-generated interpretation, and a conclusion that remains unknown.

## Multi-model discussion challenge

First demonstrate correct understanding of the objects, hypothesis, existing implementation limits and distinction between authorial approval and scientific verification. Then argue from existing computer science and archival theory. Identify the strongest possible counterexample and the smallest benchmark that could falsify the usefulness claim. Finally challenge the interpretive problem: **Can an accountable history preserve a person's right to change, and can a witness report a trajectory without becoming an unauthorized participant in creating it?**

This is a research question, not a demonstrated discovery. The correct response can be that the proposed structure offers no measurable advantage over good existing systems.
