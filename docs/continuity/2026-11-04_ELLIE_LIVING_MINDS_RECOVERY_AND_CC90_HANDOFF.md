## 3. Why a living-world runtime is different from storytelling

Documents DESCRIBE people and places. Simulators EXECUTE state transitions. The core ambition is a continuity-aware world in which source facts and corrections remain inspectable, simulated decisions remain separate, and a renderer never silently edits canon.

Five architectural layers:
1. SOURCE: original text, version, author attribution, acquisition receipt, citations, hashes, publication rights.
2. CONTINUITY: claim, status, authority, time/branch, supersession, correction and conflict history.
3. WORLD: locations, objects, people, knowledge limits, social states, equipment, scheduling constraints.
4. RUNTIME: validated actions, deterministic or receipt-replayable state transitions, simulation branches, event store, clock, policy/scheduler.
5. RENDERER: text console and 2D navigator first; 3D/voice/AR/VR/holography much later, without becoming a source of truth.

Candidate technologies discussed in the overnight work: source-to-world compiler; timeline/branch authentication; cross-model portability; actor-specific knowledge acquisition; relationship and commitment ledgers; consequence graph; trajectory from repeated choices; memory of unfinished work; controlled interactive diaries and stories; holographic embodiment limits in fiction; external scheduler with explicit activity receipts; creator-approved correction propagation; security and privacy boundaries; independent source witnesses; room rendering fed only from world state.

A claim that a character was active while the user was gone must be backed by an actually running scheduler and event receipts. No scheduler means no invented off-screen life.

The older brainstorm reportedly contained 100 candidate ideas and 10 platform primitives. The exact full original list was not retrieved here. Do NOT treat this thematic synopsis as the recovered raw 100-item list.
